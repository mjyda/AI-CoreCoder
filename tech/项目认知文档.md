# CoreCoder 项目认知文档

## 1. 项目定位

`CoreCoder` 是一个可在命令行运行的多智能体工程助手。  
当前项目重点不只是“代码问答”，而是支持：

- Supervisor + 专家（mail/browser/file/coding）协同
- 基于自然语言的动态编排（按需拼接链路）
- 执行前确认闸（确认 / 修改 / 取消）
- 会话上下文与可选持久化记忆

## 2. 核心架构（当前版本）

### 2.1 编排骨架

- `corecoder/multi_agent.py`
  - `SuperAssistant` 主入口
  - 路由决策、图执行、会话状态管理
  - 组合继承多个 mixin（编排 + 各领域任务）

### 2.2 动态计划引擎

- `corecoder/plan_engine.py`
  - `ExecutionPlanMixin`
  - 负责：
    - 动态产出执行草案（`_plan_dynamic_orchestration`）
    - 风险分级与确认策略
    - 计划执行器注册表（action -> handler）

### 2.3 领域专家逻辑拆分

- `corecoder/multi_agent_mail.py`：邮件任务逻辑
- `corecoder/multi_agent_browser.py`：浏览器任务逻辑
- `corecoder/multi_agent_file.py`：文件任务逻辑

### 2.4 会话上下文

- `corecoder/session_context.py`
  - `AssistantSessionContext`
  - 负责最近轮次摘要、最近路径、快照读写

## 3. “动态编排”如何工作

输入到达后，系统并非硬编码“固定专家直连表”，而是：

1. 解析输入中的 source/target 信号（例如邮件、浏览器、文件、发送、导出等）
2. 运行时生成 `plan`（steps、risk、requires_confirmation）
3. 返回草案并等待用户确认
4. 用户确认后按 action 执行器注册表逐步执行

你可以用 `/debug` 查看当前注册能力：

- planners
- actions
- risk policy

## 4. 运行与配置要点

### 4.1 启动

```powershell
corecoder --super-assistant
```

### 4.2 邮件配置

项目支持从 `.env` 自动加载邮件配置，且当前配置为 `override=True`（以项目 `.env` 为准）。

关键变量：

- `CORECODER_IMAP_HOST`
- `CORECODER_IMAP_PORT`
- `CORECODER_SMTP_HOST`
- `CORECODER_SMTP_PORT`
- `CORECODER_EMAIL_ADDRESS`
- `CORECODER_EMAIL_APP_PASSWORD`

## 5. 快速自检（建议）

1. 启动后执行 `/debug`，确认编排注册项存在。
2. 输入一个跨专家请求（如“最近5封邮件导出到文件...”），观察是否先出草案。
3. 回复“确认执行”，观察 steps 是否按草案执行。

## 6. 当前边界

- 已是“运行时按需拼链”，但动作仍基于已注册 action 集合。
- 新能力扩展仍需新增 action handler（见 `tech/新增Action开发文档.md`）。
