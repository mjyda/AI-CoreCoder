# 测试补齐（中文）

## 目标
为改动提供可靠的自动化验证，降低回归风险。

## 测试策略
1. 关键路径：核心业务流程必须覆盖。
2. 异常路径：无效输入、外部失败、异常分支。
3. 边界条件：空值、极值、重复输入、并发场景（如适用）。

## 实施步骤
1. 列出本次改动影响的函数/模块。
2. 先补最小必要测试，再扩展边界测试。
3. 执行测试并修复失败项。

## 反幻觉与反重复规则
1. 证据绑定
   - “测试已通过”必须绑定真实命令与结果摘要。
   - “已补齐测试”必须绑定真实文件路径与关键测试点。
2. 禁止伪造
   - 未执行命令时，禁止写“通过/失败数量”。
   - 用户要求“不要运行命令”时，切换静态模式并明确声明“未执行命令”。
   - 静态模式允许读取真实测试文件与源码（只读）；不得默认声称“无法访问项目文件”。
   - 若未读取到真实代码或测试内容，必须明确“证据不足，无法评估覆盖率”，不得给出假设性覆盖结论。
3. 文本去重
   - 同一测试点只出现一次，避免重复列表项。
   - 输出前自检并删除重复段落。
4. 失败透明
   - 测试失败时必须记录失败用例、错误摘要、后续处理，不得宣称“全部通过”。
5. 危险操作保护
   - 涉及删除/覆盖测试文件前，先说明风险并请求确认。

## 输出格式
1. 新增测试点清单
2. 实际执行命令（若未执行需明确标注）
3. 结果摘要（通过/失败数量；静态模式下标注“未执行”）
4. 仍未覆盖的风险点
