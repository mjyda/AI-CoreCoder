# 接口开发（中文）

## 目标
实现结构清晰、行为一致、可测试的 API。

## 开发步骤
1. 定义契约：输入参数、响应结构、错误码。
2. 实现路由：按资源维度组织接口。
3. 参数校验：对必填项、类型、范围做检查。
4. 错误处理：统一错误返回格式与状态码。
5. 补充文档：提供最小调用示例。

## 约束
- 成功与失败返回结构保持一致风格。
- 不吞异常；必须返回可定位信息。
- 对外接口命名保持稳定，避免无意义变更。

## 反幻觉与反重复规则
1. 证据绑定
   - “接口已实现”必须绑定真实文件路径与关键变更点。
   - “接口可用/验证通过”必须绑定真实命令与结果摘要。
2. 禁止伪造
   - 未执行验证命令时，不得写“接口可正常调用”。
   - 用户要求“不要运行命令”时，必须声明“未执行命令，以下为静态接口设计/实现说明”。
3. 文本去重
   - 同一接口变更只记录一次，避免在“列表/示例/说明”中重复堆叠。
   - 输出前删除重复段落与重复示例。
4. 失败透明
   - 验证失败时必须记录失败接口、错误摘要与修复计划，不得宣称“全部可用”。
5. 危险操作保护
   - 进行删除接口、破坏性迁移或覆盖关键文件前，先说明风险并请求确认。

## 输出格式
1. 新增或修改的 API 列表
2. 请求/响应示例
3. 错误处理策略
4. 实际执行的测试或验证命令（若未执行需明确标注）
